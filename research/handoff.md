## Things that will bite you

- **A silent no-op from the CLI looks like success.** `gh edit-issue` does not exist in this gh version (`gh issue edit` does); my first label attempt changed nothing and printed almost nothing. Re-read state after every outward mutation — it is why I know tasklight #4 has no labels and PR #3 had `state=MERGED`.
- **Config-resolution changes must be tested with an empty home.** `mkdir -p /tmp/cihome && env -u DRYDOCK_CONFIG_DIR -u DRYDOCK_REGISTRY_PATH -u PI_AGENT_DIR HOME=/tmp/cihome npm test`. On the factory host your `~/.drydock` answers whatever the code asks, which is how a half-applied seam passes locally.
- **`/health` needs the route token** (`Bearer` from `fleet/data/routes.json`, field `token`) and **ports rotate per boot**. Without the token you get `{"error":"unauthorized"}`, which looks like an outage.
- **macOS Podman cannot bind-mount `/tmp`** — scratch clones go under `$HOME/tmp` or you get `statfs … no such file or directory`, exit 125, which is infrastructure (#247) and not a test failure.
- **GitHub closing keywords in prose are live.** "fix #N" / "closes #N" anywhere in a PR body closes that issue; #256 got closed once by an accidental match this week. The previous version of *this very bullet list* had the word "fix" immediately followed by issue number 263 in a Next-action line — which would have closed it. Caught by re-reading; no scanner looks for this.
- **Do not pin running state in documents.** The version of this file that merged at 01:18Z named a supervisor PID and three ports; the fleet restarted at 01:20Z and every one of those values was wrong — including inside the paragraph warning you not to trust them. Record commands, not observations, for anything a restart changes.
- **The supervisor still reads policy at boot**, so a registry edit (including `protectedPaths`) needs a restart to take effect. Verify by the boot line's `registry sha256:…`, not by the file.
- **`test/` is writable by runs even when specific oracle files are protected.** Protection is per-path, not per-directory; check `scopeOf(entry).protectedPaths` when reasoning about what a run can touch.
